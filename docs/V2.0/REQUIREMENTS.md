# 双一流高校机械类 & 自动化类研究生导师信息爬虫 — 需求文档

> 版本：v1（定稿）｜日期：2026-09-14
> 目标：批量获取所有"双一流"及以上高校的【机械类】与【自动化类】学院研究生导师的**招生情况**与**研究方向**。

---

## 一、数据目标

| 维度 | 内容 |
|---|---|
| 学校范围 | **全部 147 所双一流高校一步到位**（985/211/其他双一流统一处理，不分批次降级） |
| 学科范围 | ① 机械类学院（机械工程、机械工程学院、精密仪器等实质对应学院）<br>② 自动化类学院（自动化学院、控制科学、机器人学院等实质对应学院） |
| 导师基础字段 | 姓名、职称（教授/副教授）、博导/硕导身份、所属学校/学院、个人主页 URL、邮箱（可选） |
| 研究方向 | 每位导师的研究方向（列表或描述文本），来自教师个人详情页 |
| **招生情况（口径：研招网招生专业目录 + 研究生院公示补充）** | ① 导师姓名（`zdjs` 字段）<br>② 招生类别（学术型/专业型）、招生方向代码与名称<br>③ 拟招生人数、考试科目<br>④ 来源 URL + 数据年份（留痕，便于逐年增量比对） |

### 数据源策略（2026-09-14 修订，含实测结论）
| 优先级 | 数据源 | 内容 | 说明 |
|---|---|---|---|
| **主数据源 A** | **各校官网师资页**（每校 list/detail spider） | 姓名、职称、博硕导身份、研究方向、邮箱 | **导师姓名唯一可靠来源**（研招网多数学校写"不区分导师"，实测覆盖率 <5%）；各校建站差异大，逐校适配 |
| **补充层 B** | **研招网招生专业目录**（yz.chsi.com.cn/zsml/） | 招生方向、拟招生人数、考试科目、学位类型、院系 | 三层 API（`dws.do`→`dwzys.do`→`yjfxs.do`）**不登录即可用**；结构化程度极高；**导师姓名字段不可用**（"不区分导师"/"请登录各学院网站"）；按"学校代码+专业代码"与 Source A 合并 |
| **补充层 C** | 各校研究生院招生导师公示 | 年度权威名单 | 格式千校千面，只在需要最终权威名单时按需抓取，parsers 插件化保留扩展能力 |

> **实测验证记录**（2026-09-14）：6所985机械工程方向 API 调研——东大8方向均"不区分导师"、西交35方向均"不区分导师"、北航2方向引向官网、清/浙/交/哈数据量1~4条且 kskmz 字段部分为空。结论：研招网价值在"招生结构化数据"而非"导师姓名"。

## 二、后端冗余设计要求

针对"各校公示页面格式差异极大"这一核心风险，后端必须满足：

1. **解析器插件化**
   - 每种公示页面模板对应一个独立 parser（如 `table_html`、`pdf_excel`、`json_api`）
   - 新增模板只加 parser 文件，不改主流程
   - 未识别格式落入 `unknown_format` 队列待人工处理，**不中断整批任务**

2. **原始数据落盘（原件与解析解耦）**
   - 公示页 HTML / PDF / Excel 原件存 `data/raw/<学校>/<年份>/`
   - 格式变化时可离线重新解析，无需重新抓取

3. **Schema 预留扩展位**
   - 每条记录包含：`raw_ref`（指向原件路径）、`source_type`（官网师资页 / 研究生院公示 / 其他）、`schema_version`
   - 未来新增字段不破坏旧数据

4. **多源合并策略**
   - 官网师资页（研究方向全）+ 研究生院公示（招生权威）按 **"姓名 + 学院"** 做软关联合并
   - 两边对不上的记录标记 `match_status: partial`，**不丢弃任何一侧数据**

5. **失败隔离**
   - 单校单源失败只记入 `failures.json`，其余任务继续
   - 提供 `--retry-failed` 命令补跑失败项

## 三、非功能要求

- **礼貌抓取**：请求间隔随机 1~3 秒；携带常规 User-Agent；失败自动重试（指数退避）
- **断点续抓**：任务粒度 = 学校 × 学院 × 数据源，已完成的默认跳过，`--force` 强制刷新
- **页面缓存加速（2026-09-20 新增）**：第一次爬取的列表页 / 教师详情页按 URL 落盘到 `data/cache/<域名>/`，后续重跑默认读本地缓存跳过网络请求，大幅加快页面刷新速度
  - 新鲜期默认 7 天（`--cache-days N` 可调），过期后降级使用旧数据（不额外发请求），`--force` 强制重新抓取并覆盖
  - `--no-cache` 可完全禁用缓存
  - API 服务层（Dashboard 触发采集）同样启用缓存
  - 并发安全：同一 URL 多线程同时访问只发一次真实请求
- **技术栈**：Python + requests/BeautifulSoup 优先；确认存在 JS 渲染依赖后再局部引入 Playwright

### 阶段 1：东南大学双链路试点（调研已完成 ✅，2026-09-14）

**1a 官网师资页链路 — 已验证，两学院机制不同：**

| 项 | 机械工程学院（me.seu.edu.cn） | 自动化学院（automation.seu.edu.cn） |
|---|---|---|
| 列表页 | `http://me.seu.edu.cn/xscz/list.htm` **纯静态 HTML，196 人全量一页无分页** | `/32668/list.htm` 静态壳为空，**必须走 JSON API** |
| 列表选择器 | `li > a[title=姓名]`，`.name`=姓名，`.research`=研究方向（列表页直接给出！），职称需进详情页 | POST `/_wp3services/generalQuery?queryObj=teacherHome`，form 参数 `siteId=338&rows=999&conditions=[...]&returnInfos=[...]`，返回 `{total:115, data:[{title(姓名), post(职称), exField1("博士生导师,硕士生导师"), cnUrl(详情链接)}]}` |
| 详情字段 | 姓名 `.carrer .jsbt`；职称/博硕导 = `.carrer .title` 裸文本；邮箱正则 `邮箱:([^\s<]+)`；研究方向 = `tit=="研究方向"` 的兄弟 `.con`（编号段落，需拆 `N、`） | 姓名 `.xing`；性别/学位/职称/导师身份为并列 `<span>`（顺序固定）；研究兴趣 = **结构化 `<p>` 列表**（板块名叫"研究兴趣"非"研究方向"，需同义词映射） |
| 特殊注意 | 个别 `.psp` 页（如陶毅）字段大量为空，解析必须容错 | 115 人含行政教辅，按 `post`/`exField1` 过滤；筛选博导用 conditions `exField1 like 博士生导师` |

- 详情页 URL **无法从拼音规律推导**（slug 带数字后缀变体），只能从列表 href / API `cnUrl` 获取；统一形态 `https://{域名}/{slug}/list.{htm|psp}`
- 反爬：无登录/验证码/Cookie 门槛，连发 6 次 <1s 间隔全部 200；API 只需 UA + Referer（加 `X-Requested-With: XMLHttpRequest` 更稳）。保守限速 ~1 req/s 即可，**无需 Playwright**
- 样本留档：`C:\Users\Public\seu\`（me_xscz.html、api_auto.json、三张详情页样本、szdw.js）

**1b 研究生院公示链路 — 部分受阻 ⚠️：**
- `gr.seu.edu.cn` 当前网络不可达；通知中官方域名为 `seugs.seu.edu.cn`（待正常网络验证）
- 替代信号三层：① 导师资格标签（博导/硕导，两院均可稳定获取，**建议作主数据**）→ ② 学院研究生培养/招生动态栏目的年度遴选公示（富文本正文，可按标题关键词"研究生/导师/复试/拟录取"过滤，机械院 `/zsdt/list.htm` 混有本科招生新闻需注意）→ ③ 研招网 yz.chsi.com.cn 年度专业目录（最终权威，含名额）
- **策略调整**：以"导师资格标签 + 研究方向"为主数据先行跑通全量；年度公示名单作为增量层每年 3~4 月补抓
